# Confirm it's you
Asks the signed-in person to prove it's still them before a sensitive action. It comes in two versions, and both use the same parts. It shows as its own dialog (`bg1`, 1px `ln1`, radius 18, padding 22, width 480–500, scrim, z 32, above drawers) or inline in a bigger dialog, inside a 1px `ac-ln` / `ac-bg` panel headed "Confirm it's you first" (the lowering dialog in Settings › Sessions). The title always names the action: "Confirm it's you to change session settings", "…to end a sign-in", "…to change Theo's role", "…to turn off MFA".

**The confirmation window.** A recent check lets one-factor actions through without asking again for the privileged idle window (10 minutes by default; it follows the admin's setting). The sample boards use 10 minutes. Any of these starts or restarts it: completing MFA at sign-in, a one-factor success, or a password-plus-factor success. The places that skip the prompt say so, with the end time worked out as the confirm time plus the window ("You confirmed it's you at 14:20, so ending a sign-in won't ask again until 14:30."). The window never lets a strong action through: those ask every time.

**One-factor.** Takes a current authenticator code (36px mono field, 6 digits, letter-spacing 4, link "Use a security key or passkey instead") or a key touch (a waiting panel with a 44px breathing `ac` key icon, "Touch your security key, or follow your browser's prompt to use a passkey.", a blinking "Waiting for your key…" line, and the links "Use an authenticator code instead" and "Try again"). Sub line (10 minutes in the sample): "You haven't confirmed in the last 10 minutes. Vigil asks again before changes like this." It's used for privileged actions, such as changing configuration or session settings, changing roles, creating a token or service account, or turning off a detection, and for ending sign-ins. This list is a set of examples, not a closed list. The final list of privileged actions comes from the permission registry.

**Strong (password plus factor).** Adds a Password field above the factor. The key path doesn't wait in the dialog; it says "After you continue, touch your security key, or follow your browser's prompt to use a passkey.". Sub line: "Changes to your sign-in methods always ask for your password and a second step." It asks **every time**, even inside the window. Someone who has lost every factor uses the recovery path (password plus a recovery code) instead. If the person confirmed recently, a `tx2` line with a lock icon says so: "You confirmed it's you at 14:20, but changes to sign-in methods ask again every time." It's used before adding or removing a security key or passkey, replacing the authenticator app, making new recovery codes, and turning off MFA. When the action has a consequence, a `fair` box above the fields names it ("Removing it signs you out of your 2 other sign-ins. This sign-in stays open." / "Turning off MFA removes your authenticator app, security keys, passkeys and recovery codes, and signs you out of your other sign-ins. To turn it back on, you'll set it up again."). The primary button names the action: Continue, Make new codes, Turn off MFA, or Remove YubiKey 5 (a plain button in `poor` outline, because a key can be added again and this check already comes first). A strong success also starts the window, so "Sign out everywhere else" straight after adding a key doesn't ask again.

**Key-only.** When an admin requires a key or passkey for the person, the authenticator path disappears: there's no "Use an authenticator code instead" link, and a `tx2` line with an info icon says "Your admin requires a security key or passkey for your account, so an authenticator code doesn't count." The password stays in the strong version.

**Errors.** Inline under the field, 12px `poor` with a warn icon, and the field border turns `poor`: "That code didn't work. Check the app and try again; codes change every 30 seconds." / "Enter your password." No error ever names which factor was right.

**Buttons.** Cancel (ghost, 34px) and the primary action (34px). There's no primary button while the dialog waits for a one-factor key touch. ARIA: `role="dialog"` with `aria-modal`; the first field takes focus; Escape cancels.
